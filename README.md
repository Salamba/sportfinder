# SportFinder

Полный код MVP: backend (Node.js/Express + SQLite), frontend (React/Vite), схема БД.
Соответствует ТЗ: роли Игрок / Организатор / Администратор, лента событий, создание
события с фото, клубы, чаты, профиль с фото.

```
sportfinder/
├── backend/     — REST API, SQLite, JWT-авторизация
├── frontend/    — React SPA (тот же дизайн, что и в интерактивном мокапе)
└── README.md    — этот файл
```

Требования: **Node.js 18+** и npm. Ничего больше ставить не нужно — база данных
SQLite создаётся автоматически файлом на диске, отдельный сервер БД не требуется.

---

## 1. Backend

```bash
cd backend
npm install
cp .env.example .env        # при желании поменяйте JWT_SECRET
npm run seed                # создаёт демо-данные (пользователи, событие, клуб)
npm run dev                 # запускает API на http://localhost:4000
```

Проверить, что сервер жив: `curl http://localhost:4000/api/health`

Демо-аккаунты после `npm run seed` (пароль везде `password123`):

| Email | Роли |
|---|---|
| viktor@example.com | Игрок, Организатор, Администратор |
| daan@example.com | Игрок, Организатор (создал демо-событие) |
| mila@example.com | Игрок |

Загруженные фото (профиля и событий) сохраняются в `backend/uploads/` и отдаются
по адресу `http://localhost:4000/uploads/<файл>`.

## 2. Frontend

Откройте второй терминал:

```bash
cd frontend
npm install
npm run dev                 # запускает SPA на http://localhost:5173
```

Откройте `http://localhost:5173` — Vite проксирует запросы `/api` и `/uploads`
на backend (порт 4000), так что настраивать CORS/URL вручную не нужно.

Войдите под одним из демо-аккаунтов или зарегистрируйтесь — новый пользователь
сразу получает роль «Игрок»; роль «Организатор» выдаётся автоматически при
создании первого события или клуба.

## 3. Что реализовано (MVP)

- Регистрация/вход по email+паролю, JWT-токен, роли Игрок/Организатор/Администратор.
- Лента событий с фильтром по виду спорта, счётчик заполненности слотов («ростер-tally»).
- Создание события: фото-обложка, вид спорта, дата/место, число мест, уровень.
- Отклик на событие, детали с составом участников.
- Клубы: создание, вступление, лента клубных событий, состав.
- Чаты по событиям и клубам (обновление раз в 3 сек — простой поллинг вместо WebSocket).
- Профиль: фото (загрузка/замена), роли, статистика, виды спорта.

## 4. Чего нет в этом MVP (осознанные упрощения)

- Реального времени в чатах (WebSocket/SSE) — сейчас поллинг раз в 3 секунды.
- Модерации/жалоб для роли Администратор (эндпоинты не реализованы, только сама роль).
- Гео-карты и расчёта расстояния — местоположение хранится как текст.
- Push-уведомлений — есть только визуальный индикатор в интерфейсе.

Это следующие шаги после MVP согласно разделу «Дальнейшие приоритеты» в ТЗ.

## 5. Структура API (backend)

| Метод | Путь | Описание |
|---|---|---|
| POST | /api/auth/register | Регистрация |
| POST | /api/auth/login | Вход |
| GET | /api/users/me | Профиль текущего пользователя |
| PATCH | /api/users/me | Обновить профиль |
| POST | /api/users/me/photo | Загрузить фото профиля |
| GET | /api/sports | Список видов спорта |
| GET | /api/events?sport=&level= | Лента событий |
| POST | /api/events | Создать событие |
| GET | /api/events/:id | Детали события |
| POST | /api/events/:id/photo | Загрузить фото события |
| POST | /api/events/:id/join | Откликнуться / вступить |
| POST | /api/events/:id/leave | Покинуть событие |
| DELETE | /api/events/:id | Отменить (только организатор) |
| GET | /api/clubs | Список клубов |
| POST | /api/clubs | Создать клуб |
| GET | /api/clubs/:id | Детали клуба |
| POST | /api/clubs/:id/join | Вступить в клуб |
| GET | /api/threads | Список чатов пользователя |
| GET | /api/threads/:id/messages | Сообщения треда |
| POST | /api/threads/:id/messages | Отправить сообщение |
